# モアイオーダー・自動登録処理手順 (Moai Order Skill)

このスキルがトリガーされた際、以下の手順を確実に実行してください。

## 1. 登録対象画像の検出
- `C:\dev\moaigame3D - コピー\images\kurima` 直下をスキャンします。
- すでに `data.js` に登録されている作品の `image` パスと一致しない「未登録の画像ファイル」を特定します。

## 2. 画像内容の読み取りと英名決定
- 未登録画像のビジュアル（文字や特徴）を読み取り、以下の情報を決定します。
  - **日本語の作品名** (例: `やったーモアイペン立て`)
  - **作品の説明文（キャッチコピー）** (例: `表情は変わらない。でも、うれしい。両手を広げて全身で喜びを表現するモアイのペン立て。`)
  - **英語ID (英名)**: 小文字の半角英数字 and アンダースコア `_` のみ (例: `yatta_moai`)

## 3. ファイル名とフォルダの作成
- 元の画像を `C:\dev\moaigame3D - コピー\images\kurima/[英語ID].jpg` (または `.png`) にリネームします。
- 詳細画像を格納するための空のフォルダ `C:\dev\moaigame3D - コピー\images\kurima/[英語ID]/` を新規作成します。

## 4. data.js へのマスター登録
- [data.js](file:///C:/dev/moaigame3D%20-%20%E3%82%B3%E3%83%94%E3%83%BC/data.js) の `MASTER_PRODUCTS` 配列の末尾に、新規作品オブジェクトを追加登録します。
- `image` や `images` 内のパスにキャッシュ対策としてタイムスタンプ等は付与せず、クリーンな相対パスを指定します。

## 5. 安全な部分コミット＆PUSH
- 他の仕掛かり中の機能（「闇の取引所」などのローカル未プッシュコード）を本番環境（GitHubの `main` ブランチ）に流出させないよう、以下の手順で **「今回の新規登録分のみ」** を `origin/main` に部分反映します。
  1. `git stash` でローカルの未コミットの変更を一時退避します。
  2. `origin/main`（リモートの最新状態）を元にした一時ブランチを作成します。
  3. 新しく追加された画像と、更新された `data.js`・`pos.html`・`catalog.html` の変更だけをコミットします。
  4. その一時ブランチから、リモートの `main` へ Push します (`git push origin temp-branch:main`)。
  5. 開発用の元のブランチ（`dev-escort-npc` など）に戻り、退避していた `git stash pop` を実行して元のローカル開発状態を復元します。
